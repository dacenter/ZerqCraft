# Анализ предметной области

## Предметная область: Обработка метеоданных, поступающих со станций

### 1. Описание предметной области

Метеорологический мониторинг представляет собой систему непрерывного сбора, обработки и анализа данных о погодных условиях. Данные поступают от распределённой сети автоматических метеостанций, установленных в различных географических точках.

### 2. Источники данных

| Источник | Описание | Частота | Объём |
|----------|----------|---------|-------|
| Температура воздуха | Датчики температуры | 1 раз/мин | ~1.4 MB/день/станция |
| Атмосферное давление | Барометрические датчики | 1 раз/мин | ~1.4 MB/день/станция |
| Влажность | Гигрометры | 1 раз/мин | ~1.4 MB/день/станция |
| Скорость ветра | Анемометры | 1 раз/мин | ~1.4 MB/день/станция |
| Направление ветра | Флюгеры | 1 раз/мин | ~1.4 MB/день/станция |
| Осадки | Плювиографы | 1 раз/мин | ~1.4 MB/день/станция |

**Оценка объёма данных:**
- 1000 станций × 8.4 MB/день = 8.4 GB/день
- За год: ~3 TB
- За 10 лет: ~30 TB

### 3. Задачи Big Data

#### 3.1 Batch-обработка (MapReduce)
- Расчёт среднесуточных/среднемесячных показателей
- Поиск экстремумов (мин/макс температура, давление)
- Выявление аномалий в данных
- Корреляционный анализ между станциями

#### 3.2 Потоковая обработка (Spark Streaming)
- Раннее предупреждение о штормах
- Мониторинг резких перепадов температуры
- Детекция неисправных датчиков
- Обновление прогнозов в реальном времени

#### 3.3 SQL-аналитика (Spark SQL)
- Ad-hoc запросы для исследователей
- Построение отчётов по регионам
- Сравнительный анализ периодов

### 4. Требования к системе

#### Функциональные требования:
- FR1: Сбор данных от 1000+ станций
- FR2: Хранение данных минимум 10 лет
- FR3: Обработка потока данных с задержкой < 5 сек
- FR4: Выполнение аналитических запросов < 1 мин

#### Нефункциональные требования:
- NFR1: Отказоустойчивость (потеря узла не должна приводить к потере данных)
- NFR2: Масштабируемость (горизонтальное добавление узлов)
- NFR3: Доступность 99.9%

### 6. Выбор технологий

| Задача | Технология | Обоснование |
|--------|------------|-------------|
| Хранение | HDFS | Распределённое хранение, отказоустойчивость, интеграция с Hadoop экосистемой |
| Batch-обработка | MapReduce | Эффективная обработка больших объёмов исторических данных |
| SQL-запросы | Spark SQL | Высокая производительность, удобный SQL-интерфейс |
| Потоковая обработка | Spark Streaming | Микро-batch обработка, интеграция со Spark SQL |
| Брокер сообщений | Apache Kafka | Высокая пропускная способность, сохранение сообщений |
| NoSQL | InfluxDB | Оптимизирована для временных рядов, встроенные агрегирующие функции |
